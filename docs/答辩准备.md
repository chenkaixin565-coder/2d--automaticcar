## 3. 高频问题与答法

| 问题 | 回答要点（30 秒内） |
|---|---|
| 为什么用 A*，不用 BFS/Dijkstra？ | 栅格 + 8 邻域 + 斜走有代价：BFS 只能等权，Dijkstra 无启发会扩太多；A* 用 octile 启发，方向性好。BFS 我保留作对照基线。 |
| 斜走为什么更省电？ | 几何长度：直行 1、斜行 √2≈1.414，两格直走是 2。耗电按长度折算，规划和执行同一套账。 |
| 视线平滑会不会穿墙？ | 平滑后逐段做 supercover 碰撞检测，任一格不可通行就退回原路径。 |
| 清障预算怎么算？ | 逐格查材质表累加，电量不够时按路径顺序截断；不会出现“预算够了但清到一半没电”。 |
| 为什么用 WebSocket？ | 状态 5Hz 推送，轮询浪费；命令走 WS，失败回退 REST；断线自动重连并补拉状态。 |
| Agent 是真 AI 吗？ | 线上是规则解析（关键词 + 正则 + 白名单），保证离线可复现；代码里留了 Ollama 通道，配置后先问模型、失败回退规则。 |
| 异常检测怎么做的？ | 规则基线（阈值/突变/冷却）+ IsolationForest 多特征；规则兜底，ML 可选。 |
| 安全怎么做的？ | 操作密钥、只读模式、指令级鉴权、限流；密钥只存 sessionStorage。 |
| 测试怎么保证？ | 后端 147、前端 112；CI 三段：lint → test → build；关键路径有回归用例。 |
| 多端怎么同步？ | 服务端唯一状态源，所有客户端收同一份 state 帧；地图变更广播 map 帧。 |
| 最大难点？ | 状态帧字段丢失导致弹窗一闪就没；定位靠“前端收到什么”逐帧打印。 |
| 如果重做会改什么？ | 状态协议先定 schema；地图编辑加乐观锁；把离线/远程服务层抽公共接口。 |

## 4. 风险预案

| 风险 | 征兆 | 处理 |
|---|---|---|
| 断网 | 页面转圈 | 切本地 `uvicorn + npm run dev`，或直接打开 GitHub Pages 静态版 |
| 线上实例休眠 | 首屏 30 秒无响应 | 提前 5 分钟打开一次唤醒；或直接用本地 |
| 端口被占 | `Errno 10048` | 换 `--port 8010`，前端地址同步改 |
| 演示数据乱了 | 电量低/障碍多 | 点“重新开始”；或“新建地图” |
| Ollama 没装 | Agent 无反应 | 讲规则通道，说明 LLM 是可选项 |
| 忘词 | — | 只看分镜表第 1 列，按时间点走 |
