# 项目需求与验收标准

> 对应模板仓库 `docs/01_项目需求.md` 的位置。用“可验证”的方式写清楚做了什么、做到什么程度。

## 1. 项目目标

在浏览器里提供一个可操作的二维巡检仿真：访客能看到地图、手动控制机器人、观察状态变化，并让机器人按巡检点自动巡检、遇到障碍时给出决策。

## 2. 使用场景

- 课堂演示：老师/同学打开网页即可操作，不需要装环境
- 答辩演示：断网也能用（本地容器或静态版）
- 二次开发：规则、地图、算法都可以单独替换

## 3. 功能范围

### 基础版（全部完成）

| 需求 | 实现 | 验收方式 |
|---|---|---|
| Web 界面 | Vue 3 页面，桌面/手机自适应 | 浏览器打开可操作 |
| 后端 API | FastAPI REST + WebSocket | `/api/v1/health` 返回 200 |
| 二维地图 | 30×20 可编辑栅格，Canvas 绘制 | 画布显示地图、起点、巡检点 |
| 手动控制 | 方向键 / 按钮 / 摇杆 | 按一次走一格，坐标同步变化 |
| 状态反馈 | 电量、速度、朝向、温度、三路传感器 | 面板数值随操作变化 |
| Git 版本管理 | 仓库 + 分支 + PR + 规范提交信息 | 提交历史可查 |
| 基础 CI | GitHub Actions：lint / test / build | 每次 push 三项通过 |
| Docker 部署 | 多阶段构建单容器镜像 | `docker run -p 8000:8000` 可访问 |

### 标准版（四个方向全部完成）

| 方向 | 实现 | 验收方式 |
|---|---|---|
| 自动巡检 | 多点顺序巡检、单点任务、暂停/继续、遇阻决策 | 巡检能走完并结束 |
| 路径规划 | 八邻域 A*（octile 启发、斜行 √2、不切墙角、视线平滑），BFS 对照 | 规划路线可通行、可复现 |
| 虚拟传感器 | 三路超声 + 温度 + 电量，带噪声与故障注入 | 数值随位置变化 |
| 异常处理 | 规则基线 + IsolationForest；遇阻弹窗（清除/跳过/停止） | 触发后弹窗并可处理 |

### 进阶版（已完成）

| 方向 | 实现 | 说明 |
|---|---|---|
| AI 模型 | IsolationForest 异常检测（规则兜底） | 无 GPU 也能跑 |
| Agent | 10 个白名单工具、二次确认、自然语言 | 线上规则解析；可选本地 Ollama |
| 复杂控制 | 单点巡检、按规划清障、返航充电、回放 | 见 README 功能清单 |

## 4. 可验收的关键行为

1. **不能穿墙**：起点 (1,1)，(2,1) 是障碍，按“右”后坐标仍为 (1,1)，并返回受阻提示。
2. **规划是预览**：点“预览规划路线”只显示路线和耗电，机器人不动；点“前往”才移动。
3. **预算按材质**：石头 5%、沙子 2%、金刚石 20%，逐格累加；电量不足时按路径顺序截断。
4. **遇阻不静默**：巡检中无法到达时暂停并弹窗，可选“清除 / 跳过 / 停止”。
5. **清障后地图同步**：清掉障碍后，画布上的障碍立即消失（`map` 帧覆盖）。
6. **只读保护**：没有操作密钥时，改地图会先弹密钥框，本地一格都不改。
7. **断网可演示**：容器内已包含前端与规则，断网仍能跑；静态版可离线仿真。

## 5. 非功能要求

| 项 | 要求 | 现状 |
|---|---|---|
| 状态刷新 | ≥ 5 Hz | 200ms 一帧 |
| 首屏 | 普通电脑 2 秒内可交互 | 前端构建产物 < 300KB（gzip） |
| 兼容 | Chrome / Edge / 手机浏览器 | 已适配 |
| 安全 | 写操作需密钥；只读模式；限流 | 已实现 |
| 可维护 | 规则单一来源；模块边界清晰 | 见 `docs/architecture.md` |

## 6. 明确不做的范围

- 真实机器人/硬件接入（无设备）
- 多机协同调度
- 云端大模型默认开启（需要 GPU 或付费 API，改为可选 Ollama）
- 用户系统/数据库（当前为单会话内存态，重启即重置）
