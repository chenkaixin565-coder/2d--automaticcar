# 路径规划与巡检调度说明

> 适用版本：**V2.3.0**
> 对应代码：`backend/app/algorithms/astar.py`、`bfs.py`、`smoothing.py`、
> `services/patrol.py`、`services/simulation_engine.py`
> 本文所有性能数字由 `backend/tools/benchmark_paths.py` 实测生成，命令与随机种子见第 7 节；
> 原始统计保存在 `docs/benchmark-paths.json`。

---

## 1. 问题定义

地图是 `W × H` 的二维栅格，`0` 可通行、`1` 普通障碍、`2` 固定屏障。需要解决三类问题：

1. **单点最短路**：从当前位置到某个巡检点；
2. **多点巡检**：给定若干巡检点，决定访问顺序并为每段寻路；
3. **动态重规划**：行进途中路径被新障碍截断时的处理。

V2.3.0 起支持两种移动模型：

| 模式 | 邻居 | 一步代价 | 启发函数 | 用途 |
|---|---|---|---|---|
| 八邻域（默认） | 8 | 直行 1、斜行 √2 | octile | 日常巡检、路线预览 |
| 四邻域 | 4 | 恒为 1 | 曼哈顿 | `/path?diagonal=false`、与 BFS 对照 |

**电量口径**：移动耗电按走过的几何长度折算（直行 0.2%/格、斜行 0.2%×√2），
这样"规划预览算出来的耗电"和"实际跑完扣的电"是同一套账。

**清障口径（V2.4.0）**：清障按"材质"计价，单价写在 `shared/simulation-rules.json`：

| 格子值 | 材质 | 单处清障耗电 |
|---|---|---|
| 1 | 石头 | 5% |
| 3 | 沙子 | 2% |
| 4 | 金刚石 | 20% |

规划时逐格查表累加（而不是"障碍个数 × 统一单价"），电量不足以清完时按路径顺序截断。

## 2. A* 实现

### 2.1 估价函数

八邻域使用 **octile 距离**：

```
dx, dy = |n.x - goal.x|, |n.y - goal.y|
h(n) = (dx + dy) + (√2 - 2) · min(dx, dy)
```

即"先沿对角线走到只剩一个坐标差，再走直线"的几何长度。四邻域使用曼哈顿距离
`h(n) = dx + dy`。

**可采纳性**：八邻域中每走一步，`dx + dy` 最多减少 `1 + √2`；而 octile 距离恰好
等于无遮挡时的最短几何长度，任何可行路径的代价都不会小于它，故 `h(n) ≤ h*(n)`。
**一致性**：对任意相邻节点 `n → n'`，有 `h(n) ≤ c(n, n') + h(n')`，因此每个节点
只需展开一次（代码里的 `closed` 集合就是据此安全跳过的）。

> 常见错误：开了八邻域却仍用曼哈顿距离。曼哈顿会高估对角路径的代价，A* 退化为
> 次优；本项目在 `astar.py` 里把邻居集合和启发函数绑定选择，避免两处不同步。

### 2.2 禁止斜穿墙角

斜向移动 `(dx, dy)` 时，额外要求 `(x+dx, y)` 与 `(x, y+dy)` 都可通行：

```
if not free(x+dx, y) or not free(x, y+dy): 跳过该邻居
```

否则机器人会被想象成从两个障碍的缝隙里"挤"过去，路径在物理上不可执行。
单元测试 `test_no_corner_cutting` 用一个被两格障碍夹死的起点验证：允许斜穿时能
"逃出去"，禁止后必须判定为 `unreachable`。

### 2.3 数据结构

| 结构 | 选型 | 原因 |
|---|---|---|
| 开放列表 | `heapq`，元素 `(f, h, 自增计数, x, y)` | 取最小 `f` 为 O(log n)；`h` 作第二键实现 tie-breaking，优先朝目标展开，路径更直 |
| 已访问代价 | `dict[node] = g` | 稀疏存储，避免为整张地图开数组 |
| 前驱表 | `dict[node] = parent` | 成功后回溯路径 |
| 关闭集合 | `set` | 出堆即标记，防止重复展开 |

`visited_count` 在节点**出堆**时自增，代表真正展开的节点数，与 BFS 口径一致。

### 2.4 伪代码

```
push (h(start), h(start), start)
while heap 非空:
    current = pop 最小 (f, h)
    if current in closed: continue
    closed.add(current); visited_count += 1
    if current == goal: 回溯并返回
    for (dx, dy) in 邻居(current):
        if 越界 or 障碍 or 已关闭: continue
        if 斜向 and 任一侧正交格是障碍: continue      # 禁止斜穿墙角
        step = 1 if 直行 else √2
        g' = g[current] + step
        if g' < g[neighbor]:
            g[neighbor] = g'; parent[neighbor] = current
            push (g' + h(neighbor), h(neighbor), neighbor)
return 空路径（不可达，error = "unreachable"）
```

### 2.5 复杂度

- 时间：`O(E log V)`，网格中 `V = W·H`、`E ≤ 8V`，最坏 `O(W·H·log(W·H))`
- 空间：`O(V)`（开放列表 + 代价表 + 前驱表）
- 实测 200×200、20% 障碍：八邻域平均 **6.3 ms**（P95 15.2 ms），远低于课程要求的 200 ms

## 3. 路径平滑（V2.3.0 新增）

八邻域 A* 的路径已经比较直，但遇障绕行后仍会留下"台阶式"冗余拐点。
`smoothing.py` 做两件事：

1. **视线抽稀**（string pulling）：从锚点出发，用**超覆盖 Bresenham** 判断到后续点
   是否通视，尽量把视线延伸到最远；只保留必须转弯的点。
   超覆盖版本会把"线段恰好擦过两个格的公共角点"两侧的格都算进来，避免把擦墙
   误判为通视。
2. **逐格回填**：抽稀后相邻关键点可能隔好几格，而仿真引擎每 tick 只走 `path[1]`。
   因此再用同一条超覆盖线段把关键点之间填回相邻格，保证机器人仍然逐格执行、
   电量与 tick 数都不失真。

回填后的路径长度不会超过原路径；一旦实现异常变长，`smooth_and_expand()` 直接
退回原路径（防御式写法）。单次视线检查最多跨 32 格，整体开销与控制路径长度成线性。

## 4. 与 BFS 的对照实验

BFS 在无权图上按层扩展，保证最短步数，但没有方向性，会向四周均匀铺开。
A* 用启发函数把搜索拉向目标，因此扩展节点更少。

**实验设置**：`50×50` 与 `200×200` 网格，内部 20% 随机障碍，四周为墙；随机取可通行
起点/终点，只统计可达样本；50×50 共 100 组、200×200 共 20 组，随机种子 `20261030`；
同一台机器串行计时。

| 地图 | 算法 | 平均扩展节点 | P95 扩展 | 平均耗时 | 平均代价 |
|---|---|---|---|---|---|
| 50×50 | A*（八邻域） | 139.5 | 398 | 0.50 ms | **29.6** |
| 50×50 | A*（四邻域） | **87.9** | 226 | **0.20 ms** | 34.0 |
| 50×50 | BFS（四邻域） | 917.4 | 1757 | 0.60 ms | 34.0 |
| 200×200 | A*（八邻域） | 1553.2 | 4156 | 6.3 ms | **105.6** |
| 200×200 | A*（四邻域） | **841.3** | 1909 | **2.0 ms** | 122.3 |
| 200×200 | BFS（四邻域） | 13241.5 | 26544 | 11.8 ms | 122.3 |

结论（可直接用于答辩）：

- 八邻域 A* 只扩展了 BFS 的 **15.2%**（50×50）与 **11.7%**（200×200）节点；
- 四邻域 A* 与 BFS 在 100/100（50×50）、20/20（200×200）组样本上最优代价完全一致，
  说明启发函数没有破坏最优性；
- 八邻域相对四邻域：路径几何长度平均缩短 **12.9%**（29.6 vs 34.0），
  步数减少 **22.4%**；代价是多展开约 59% 的节点（分支因子更大）、耗时约 2.5 倍；
- 因此本项目**默认八邻域**（演示时路径好看、耗电更省），`/path` 调试接口保留
  `diagonal=false` 用于对照实验与 BFS 基准。

> **不要手工修改表格数字**：改代码后重跑 `benchmark_paths.py`，它会同时刷新
> `docs/benchmark-paths.json`。

## 5. 多点巡检调度

`services/patrol.py::order_goals_by_nearest` 采用**最近邻贪心**：

1. 从机器人当前位置出发，计算到每个未访问巡检点的曼哈顿距离；
2. 选最近的一个作为下一目标；
3. 到达后从该点继续选下一个，直到全部访问。

每一段用 A* 求实际路径（不是直线距离），因此墙体会被绕开。若某点不可达：

- 记录一条 `obstacle` 异常事件（"无法到达巡检点 [x,y]，已跳过"）
- 跳过该点，继续下一个，最多尝试完所有点后结束任务

进度以 `completed / total` 与 `progress`（0–1）同时暴露，前端进度条直接使用。

> 最近邻是启发式排序，不保证全局最短（这是旅行商问题的近似解）。差距随点位分布
> 变化，本文不做定量承诺；换来的是 O(n²) 的简单实现与可解释性，适合 5 个点左右的
> 演示规模。

## 6. 动态重规划

巡检跟随路径时，如果下一格被新障碍占据，`simulation_engine._handle_patrol_blocked`
按两级处理：

| 级别 | 条件 | 行为 |
|---|---|---|
| 1 | 从当前格到当前巡检点仍存在路径 | 立即用 A* 重算，替换剩余路径，继续巡检（发 notice「已自动绕开障碍」） |
| 2 | 完全封死 | 暂停，记录 `blocked_by`，发 `blocked` 帧，等待用户三选一 |

用户三选一：

- `clear`：扣 5% 电量清除该障碍，重算当前段，继续；
- `skip`：把障碍记入待清障列表，跳到下一个巡检点；
- `stop`：结束任务，回到手动模式。

重规划同样走 `smooth_and_expand()`，因此"绕一下再回来"的新路径不会留下多余台阶。

## 7. 低电量回充闭环

```
电量 < 20%  →  mode = charging
            →  A* 规划到 charge_point（只走可通行格；障碍与固定屏障都不穿越）
            →  到点后每 tick 恢复 1%
            →  充满 100% 且此前在巡检 → 自动继续原任务
```

V2.3.0 的 Agent 指令层复用了同一条路径：`go_charge` 工具调用
`engine.go_charge()`，效果与低电量自动返航一致（区别只是"手动让它去"，不会触发
低电量告警）。若充电点不可达，返回提示并保持原状态，不会原地"假装充电"。

## 9. 已知边界

1. **单机器人**：全局只有一个仿真引擎实例，多机调度需要扩展为按 robot_id 的状态表；
2. **静态代价**：每格代价只有"直行 / 斜行"两种，没有考虑地面摩擦、转弯代价、拥堵；
3. **八邻域不等于任意角度**：路径仍是 45° 的整数倍，不是真正的任意曲线；若要更
   顺滑的轨迹，需要引入 Dubins/Reeds-Shepp 曲线或纯跟踪控制器；
4. **最近邻非全局最优**：巡检点数量增大时，与最优顺序的差距会扩大；
5. **没有 D\* Lite / MAPF**：动态重规划是"从头重算当前段"，不是增量式搜索；
   多机协同避让也未实现。

这些边界不影响"二维栅格仿真"的定位，但在答辩时应主动说明，避免被理解为"已经能
调度真实仓库的几十台 AGV"。
