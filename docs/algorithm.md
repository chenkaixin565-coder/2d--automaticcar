# 路径规划与巡检调度说明

> 适用版本：**V2.2.1**
> 对应代码：`backend/app/algorithms/astar.py`、`bfs.py`、`services/patrol.py`、`services/simulation_engine.py`
> 本文所有性能数字由 `backend/tools/benchmark_paths.py` 实测生成，命令与随机种子见第 7 节。

---

## 1. 问题定义

地图是 `W × H` 的二维栅格，`0` 可通行、`1` 普通障碍、`2` 固定屏障。机器人在四邻域
（上/下/左/右）移动，一步代价为 1。需要解决三类问题：

1. **单点最短路**：从当前位置到某个巡检点；
2. **多点巡检**：给定若干巡检点，决定访问顺序并为每段寻路；
3. **动态重规划**：行进途中路径被新障碍截断时的处理。

---

## 2. A* 实现

### 2.1 估价函数

四邻域、单位步长下采用曼哈顿距离：

```
h(n) = |n.x - goal.x| + |n.y - goal.y|
```

**可采纳性**：四邻域每步最多让曼哈顿距离减少 1，因此从 `n` 到目标的真实代价
`h*(n) ≥ h(n)`，启发函数不会高估，A* 保证最优。
**一致性**：对任意相邻节点 `n → n'`，有 `h(n) ≤ 1 + h(n')`，因此无需重复展开已关闭节点。

> 如果将来开启 8 方向（对角步长 1 或 √2），曼哈顿距离会高估对角路径，**必须换成
> octile 距离** `max(dx,dy) + (√2-1)·min(dx,dy)`，并禁止斜穿墙角，否则最优性失效。

### 2.2 数据结构

| 结构 | 选型 | 原因 |
|---|---|---|
| 开放列表 | `heapq` 最小堆，元素 `(f, 自增计数, 节点)` | 取最小 `f` 为 O(log n)；计数位避免 `f` 相同时比较元组报错 |
| 已访问代价 | `dict[node] = g` | 稀疏存储，避免为整张地图开数组 |
| 前驱表 | `dict[node] = parent` | 成功后回溯路径，空间与展开节点数成正比 |

`visited_count` 在节点**出堆**时自增，代表真正展开的节点数，与 BFS 的口径一致。

### 2.3 伪代码

```
push (h(start), start)
while heap 非空:
    current = pop 最小 f
    visited_count += 1
    if current == goal: 回溯并返回
    for neighbor in 四邻域(current):
        if 越界 or 障碍: continue
        g' = g[current] + 1
        if g' < g[neighbor]:
            g[neighbor] = g'
            parent[neighbor] = current
            push (g' + h(neighbor), neighbor)
return 空路径（不可达）
```

### 2.4 复杂度

- 时间：`O(E log V)`，网格中 `V = W·H`、`E ≈ 4V`，最坏 `O(W·H·log(W·H))`
- 空间：`O(V)`（开放列表 + 代价表 + 前驱表）
- 实测 200×200、20% 障碍：平均 **3.37 ms**，P95 **9.04 ms**，远低于课程要求的 200 ms

## 3. 与 BFS 的对照实验

BFS 在无权图上按层扩展，保证最短步数，但没有方向性，会向四周均匀铺开。
A* 用曼哈顿距离把搜索拉向目标，因此扩展节点更少。

**实验设置**：50×50 网格，内部 20% 随机障碍，四周为墙；随机取可通行起点/终点，
只统计可达样本；共 100 组，随机种子 `20261027`；同一台机器串行计时。

| 算法 | 平均扩展节点 | 平均耗时 | 最优代价一致率 |
|---|---|---|---|
| A*（曼哈顿，四邻域） | **178.9** | **0.24 ms** | 100 / 100 |
| BFS（对照基线） | 881.8 | 0.58 ms | 100 / 100 |

结论：

- 在 20% 障碍的 50×50 地图上，A* 只扩展了 BFS 的 **20.3%** 节点，耗时约为其 **41%**；
- 两者 100 组样本的最优代价完全一致，说明 A* 的启发函数与实现没有破坏最优性；
- 扩展到 200×200 时差距更大：A* 平均扩展 **2333.7** 个节点，BFS 为 **15563.1**（**15.0%**）；
  耗时 3.37 ms vs 11.87 ms。

> 这组数字就是答辩时"启发式搜索比盲目搜索省多少"的直接答案，也是本文表格的数据来源。
> 原始统计保存在 `docs/benchmark-paths.json`；复现命令见第 7 节。
> **不要手工修改表格数字**，改代码后重跑脚本。

## 4. 多点巡检调度

`services/patrol.py::order_goals_by_nearest` 采用**最近邻贪心**：

1. 从机器人当前位置出发，计算到每个未访问巡检点的曼哈顿距离；
2. 选最近的一个作为下一目标；
3. 到达后从该点继续选下一个，直到全部访问。

每一段用 A* 求实际路径（不是直线距离），因此墙体会被绕开。若某点不可达：

- 记录一条 `obstacle` 异常事件（"无法到达巡检点 [x,y]，已跳过"）
- 跳过该点，继续下一个，最多尝试完所有点后结束任务

进度以 `completed / total` 与 `progress`（0–1）同时暴露，前端进度条直接使用。

> 最近邻是启发式排序，不保证全局最短（这是旅行商问题的近似解）。差距随点位分布变化，
> 本文不做定量承诺；换来的是 O(n²) 的简单实现与可解释性，适合 5 个点左右的演示规模。

## 5. 动态重规划

巡检跟随路径时，如果下一格被新障碍占据，`simulation_engine._handle_patrol_blocked`
按两级处理：

| 级别 | 条件 | 行为 |
|---|---|---|
| 1 | 从当前格到当前巡检点仍存在路径 | 立即用 A* 重算，替换剩余路径，继续巡检（发 notice「已自动绕开障碍」） |
| 2 | 完全封死 | 暂停，记录 `blocked_by`，发 `blocked` 帧，等待用户三选一 |

用户三选一：

- `clear`：扣 5% 电量清除该障碍，重算当前段，继续；
- `skip`：把障碍记入待清障列表，跳到下一个巡检点；
- `stop`：结束任务，回到手动模式。

这样既不会"遇障就停"打断演示，也不会在无路可走时假装继续。

## 6. 低电量回充闭环

```
电量 < 20%  →  mode = charging
            →  A* 规划到 charge_point（只走可通行格；障碍与固定屏障都不穿越）
            →  到点后每 tick 恢复 1%
            →  充满 100% 且此前在巡检 → 自动继续原任务
```

若到充电点无路可走（被障碍或固定屏障封死），返回 `empty` 状态并提示用户搬回起点（`POST /robot/carry-home`）。
相关阈值来自 `shared/simulation-rules.json`，前后端共用同一份。

## 8. 已知边界

1. **仅四邻域**：路径是直角折线，没有 8 方向的斜线，也没有视线法平滑；
2. **单机器人**：全局只有一个仿真引擎实例，多机调度需要扩展为按 robot_id 的状态表；
3. **静态代价**：每格代价恒为 1，没有考虑地面摩擦、转弯代价、拥堵；
4. **最近邻非全局最优**：巡检点数量增大时，与最优顺序的差距会扩大。

这些边界不影响"二维栅格仿真"的定位，但在答辩时应主动说明，避免被理解为"已经能调度
真实仓库的几十台 AGV"。
