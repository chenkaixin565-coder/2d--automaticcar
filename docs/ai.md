# 感知与异常检测模块设计说明

> 对应角色：人工智能工程师
> 范围：虚拟传感器仿真、轻量机器学习异常检测、异常事件管理
> 约束：**纯本地计算**，只用 `numpy + scikit-learn`，不调用任何付费大模型 API、不依赖 GPU

---

## 1. 概述

本模块在仿真引擎的每一个 tick（默认 200ms）产生一组传感读数，并实时判断机器人是否处于异常状态。全部计算在后端进程内完成，单次推理 < 5ms（CPU），满足"数据量小、无 GPU、可解释、够用"的硬约束。

异常检测采用**双策略并行、配置切换**的设计：

- **规则基线（默认）**：阈值法，作为兜底与对照，逻辑直观、零冷启动。
- **机器学习（IsolationForest）**：对滑动窗口内的多维传感数据做在线异常打分，能发现规则难以覆盖的"组合型异常"（例如温度略高 + 距离抖动 + 电量缓降同时发生）。

两条策略都输出统一结构的 `AnomalyEvent`，通过 WebSocket 的 `anomaly` 帧即时推送到前端。

---

## 2. 特征设计

每个 tick 采集一条 5 维特征向量：

| 维度 | 含义 | 来源 | 正常区间 |
|------|------|------|----------|
| `battery` | 电量百分比 | 仿真引擎（移动耗电 + 自放电噪声） | 0–100，平滑下降 |
| `temperature` | 机身温度 ℃ | 虚拟温度传感器 | 35 + 运动温升 + 噪声 |
| `front` | 前向测距 m | 三向超声波射线 | 0–5，平滑变化 |
| `left` | 左向测距 m | 三向超声波射线 | 0–5，平滑变化 |
| `right` | 右向测距 m | 三向超声波射线 | 0–5，平滑变化 |

选这 5 维的原因：它们共同刻画了"机器人是否在健康地运动"。任何一维的突变、或几维的异常组合，都可能是故障前兆。读数缺失（射线超程返回 `None`）统一用量程上限（5m）填充，保证特征向量维度恒定、模型输入稳定。

---

## 3. IsolationForest 原理简述

Isolation Forest（孤立森林）由 Liu 等人于 2008 年提出，核心思想非常朴素：**异常点少且"与众不同"，因此更容易被随机划分孤立出来。**

- **孤立树（iTree）**：对特征空间反复做随机超平面切割，直到每个样本被单独隔离或达到树高上限。
- **路径长度 `h(x)`**：样本 `x` 从根到被孤立所经过的边数。异常点因为"好分"，路径通常很短。
- **异常分数 `s(x)`**：由路径长度归一化得到，取值范围约 `(-0.5, 0.5]`。`s` 越接近 1，越可能是异常；我们取 `s < threshold`（负向越界）触发告警。

相比基于距离的算法，IsolationForest **不需要计算样本间距离**，训练和推理都是亚毫秒级，天然适合 200ms 一次的在线场景。

### 为什么选它，而不是深度学习

| 维度 | IsolationForest | 深度学习（如 AutoEncoder） |
|------|-----------------|----------------------------|
| 数据量 | 小样本即可（百级） | 需要大量正常样本训练 |
| 硬件 | 纯 CPU，无 GPU | 通常依赖 GPU 才划算 |
| 可解释性 | 路径长度直观 | 黑盒，难解释 |
| 本场景适配 | 足够覆盖组合异常 | 杀鸡用牛刀，易过拟合 |

结论：在本项目"小数据、无 GPU、要可解释"的约束下，IsolationForest 是性价比最高的选择。

## 4. 双策略架构与切换

```
tick()
  ├─ sensors.read_all()        # 三向测距 + 温度（+ 故障注入开关）
  ├─ anomaly_detector.update(reading)   # 规则 + ML 双通道
  │     ├─ 规则基线：阈值法（低电量/过热/传感器突变）
  │     └─ ML：滑动窗口 120 tick → IsolationForest 打分
  └─ 输出 AnomalyEvent[] → WebSocket 推送
```

通过配置项 `ANOMALY_STRATEGY=rule|ml` 切换。默认 `rule`，保证开箱行为与验收基线一致；演示机器学习效果时切到 `ml`。

---

## 5. 冷启动与增量重训

- **冷启动**：引擎以"正常模式"自动采集 `ML_COLDSTART_TICKS`（默认 500）个 tick 的传感数据，训练首个 IsolationForest 模型。
- **在线推理**：之后每个 tick 把最新特征追加到长度为 120 的滑动窗口，窗口内做异常打分。
- **增量重训**：每 `ML_RETRAIN_SECONDS`（默认 60）秒，用最近窗口数据重新拟合一次模型，适应温度基线漂移等缓慢变化。重训在独立线程内进行，**不阻塞仿真主循环**。

---

## 6. 特征标准化与阈值校准

实验中发现两个关键点，直接决定了检测器形态：

1. **特征必须标准化**。电量跨度约 40、温度/距离跨度约 5，量纲差异大；若不标准化，随机割裂会被电量主导，温度/距离异常被淹没。故用训练段的均值/方差对 5 维特征做 z-score 标准化，让各维贡献均衡。
2. **阈值按正常分布自动校准**。固定魔法阈值（如 -0.5）在本数据上会落到正常分数分布中段，导致误报飙高（实测可达 60%）。改为取正常段异常分数的低分位（`ML_SCORE_PERCENTILE`，默认 2%）作为阈值，把误报率控制在该水平；也可用 `ML_SCORE_THRESHOLD` 指定固定值覆盖。

阈值作为配置项暴露，便于演示时现场调。

---

## 7. 传感器故障模拟开关

配置项 `SENSOR_FAULT_PROB`（默认 0，关闭）。开启后，每个 tick 以该概率让某个传感器输出**离群值或恒定值**，用于演示异常检测效果：

- 离群值：在真实读数上叠加大幅随机偏移；
- 恒定值：卡死在某个固定读数（模拟探头失效）。

前端"开启故障模拟"后，规则策略会在 1 分钟内捕获突变告警；机器学习策略会更早识别出偏离正常分布的模式。

## 8. 实验评估（实测回填）

在合成数据集上评估（`tests/test_anomaly_ml.py`，随机种子固定、可复现）：

| 策略 | 正常段误报率 | 故障段召回率 | 单次推理耗时 |
|------|--------------|--------------|--------------|
| 规则基线 | ≈0%（阈值未越界不报警） | 三类已知故障越阈即报 | < 0.1ms |
| IsolationForest（标准化 + 2% 分位校准） | 2.0% | 组合型：三向失灵 100%、温度+贴障 67%、温度+低电量 49% | < 1ms |

**关键结论（答辩要点）**：两条策略是**互补**而非竞争关系——

- **规则基线**擅长"单维超范围 / 阈值型"故障：温度飙到 60℃、传感器钉到 0、电量跌破 20%，阈值一越就报，直观、近零误报、零冷启动。
- **IsolationForest** 擅长"分布内的组合型异常"：单个读数都还在合理量程，但组合在正常工况下几乎不出现（如三向探头同时贴低、温度与距离背离）。这类故障难以用单阈值表达，正是孤立森林的靶子。
- 实测也印证了边界：对单维外推故障，IsolationForest 召回仅约 20%（割裂点来自训练范围，对外推不敏感），此时应信赖规则基线。

因此默认策略为 `rule` 兜底，`ml` 作为能力展示与组合型异常补充。

## 9. 接入说明（给全栈工程师）

在仿真主循环里只需两步：

```python
# 1) 引擎初始化时按策略创建检测器（已在 engine.__init__ 内完成）
from app.services.anomaly import create_detector
self.anomaly_detector = create_detector(config.settings.anomaly_strategy)

# 2) 每个 tick 把传感器读数喂进去，拿到异常事件
reading = self.sensor_sim.read_all(self.x, self.y, self.theta, self.battery, moving)
events = self.anomaly_detector.update(reading)   # list[AnomalyEvent]
for e in events:
    self._emit_anomaly(e)
```

`create_detector` 在 `rule` 与 `ml` 之间返回不同实现，对调用方透明。ML 策略的冷启动采集、增量重训、滑动窗口全部封装在检测器内部，主循环无感知。
