# 自然语言 Agent 指令层说明

> 适用版本：**V2.3.0**
> 对应代码：`backend/app/services/agent.py`、`backend/app/api/rest.py`（`/agent/*`）、
> `frontend/src/services/agent.js`、`frontend/src/components/AgentPanel.vue`
> 相关测试：`backend/tests/test_agent.py`（30 例）、`frontend/src/services/__tests__/agent.test.js`（22 例）

---

## 1. 这一层解决什么问题

V2.2.1 的操作路径是"点按钮 / 拖地图"：用户必须先理解界面，才能让机器人做事。
V2.3.0 增加一层自然语言入口：用户说一句话，系统把它翻译成一个**受控的工具调用**，
再交给已有的仿真引擎执行。

它对应策划书"进阶版"里的两项：**AI 模型**（可选的本地大模型）与 **Agent**
（指令理解 → 工具选择 → 执行 → 汇报的闭环）。关键不是"接了个大模型"，而是
**大模型只负责选工具，权限、参数与安全边界都在确定性代码里**。

```
用户一句话
   │
   ▼
┌─────────────────────────────┐
│ 解析器（二选一）             │
│  · 内置中文规则（默认，离线） │
│  · 本地 Ollama（可选，失败回退）│
└──────────────┬──────────────┘
               │ {tool, args}
               ▼
┌─────────────────────────────┐
│ 白名单 + schema + 业务校验    │  ← 越界、非障碍、电量不足、边界编辑…
└──────────────┬──────────────┘
               │ 合法参数
               ▼
┌─────────────────────────────┐
│ 破坏性操作？ → need_confirm   │  ← 清障 / 改图 / 复位 / 新建地图
└──────────────┬──────────────┘
               │ confirm=true
               ▼
      仿真引擎（与按钮完全同一套方法）
               │
               ▼
      一句人话 + 结构化 result
```

## 2. 工具白名单

模型只能从下表里选动作，**不能生成代码、不能拼 URL、不能调用未注册接口**。

| 工具 | 参数 | 破坏性 | 说明 |
|---|---|---|---|
| `status` | — | 否 | 位置、朝向、电量、模式、巡检进度、待清障数 |
| `plan_route` | `goal:[x,y]` | 否 | 只生成路线预览，不移动机器人 |
| `start_patrol` | `goals?:[[x,y]]` | 否 | 开始巡检，缺省用地图巡检点（上限 12 个） |
| `stop_patrol` | — | 否 | 停止巡检 |
| `go_charge` | — | 否 | 返回充电点（复用低电量返航状态机） |
| `move` | `dx,dy ∈ {-1,0,1}` | 否 | 手动移动一格，含"前进/后退"按当前朝向解释 |
| `clear_obstacle` | `cell:[x,y]` | **是** | 清障，扣 5% 电量，目标是屏障或空地会被拒绝 |
| `set_cell` | `x,y,value∈{0,1,2}` | **是** | 编辑地图，禁止编辑边界与关键格 |
| `reset` | — | **是** | 复位并恢复满电 |
| `new_map` | `width,height ∈ [10,60]` | **是** | 新建空白地图 |

`GET /api/v1/agent/tools` 返回同一份清单，前端示例与文档都从它取。

## 3. 安全边界（答辩重点）

| 风险 | 对应措施 |
|---|---|
| 模型幻觉，生成不存在的动作 | 白名单：`validate_call` 第一行就拒绝未知工具 |
| 模型给出越界 / 非法坐标 | 参数 schema + 边界检查，执行前拦截并返回中文原因 |
| 模型把障碍当通行格 | 业务校验：巡检点必须可通行、清障目标必须是普通障碍 |
| 模型"擅自拆墙" | 破坏性操作二次确认：第一次只返回 `need_confirm`，不执行 |
| 一句话下发超长任务 | `AGENT_MAX_GOALS`（默认 12）限制巡检点数量 |
| 大模型服务不可用 | 6 秒超时后自动回退规则解析，界面不会卡住 |
| 任意访问者控制机器人 | Agent 接口属于写操作，沿用 `OPERATOR_KEY` / `READONLY_MODE` 鉴权 |
| 大模型把内网信息带走 | 只调用配置里的本地 Ollama 地址，不向任何第三方转发 |

另一个容易被忽略的点：**执行结果以引擎为准，不以模型的话为准**。例如模型说"已清除"，
但引擎因为电量不足没有清，返回体里的 `ok=false` 与 `message` 会如实反映，
前端展示的是引擎的结论。

## 4. 两种解析器

### 4.1 规则解析（默认，离线可用）

`parse_rules()` 是一组按优先级排列的中文关键词 + 坐标正则：

| 说法 | 工具 |
|---|---|
| "停止 / 别走了" | `stop_patrol` |
| "状态 / 电量 / 在哪" | `status` |
| "回充电点 / 返航" | `go_charge` |
| "清除 / 拆掉 + 坐标" | `clear_obstacle` |
| "巡检 / 巡逻 + 坐标" | `start_patrol` |
| "规划 / 路线 / 怎么走 + 坐标" | `plan_route` |
| "复位 / 回起点" | `reset` |
| "新建 30x20 地图" | `new_map` |
| "把 5,5 设成屏障" | `set_cell` |
| "前进 / 后退 / 向上 / 向右" | `move` |
| 只有坐标 + "去/到" | `plan_route`（只预览，保守） |

坐标支持 `5,5`、`(5，5)`、`5、5`、`5x5` 等写法。识别不了就返回"没听懂"，
不会猜一个动作去执行——**宁可不动，也不乱动**。

### 4.2 本地大模型（可选）

设置环境变量后启用：

```bash
AGENT_LLM_ENABLED=true
AGENT_OLLAMA_URL=http://127.0.0.1:11434
AGENT_OLLAMA_MODEL=qwen2.5:7b
AGENT_LLM_TIMEOUT_S=6
```

调用 `/api/chat`，`format=json`、`temperature=0`，系统提示词里列出白名单与参数格式，
要求只输出 `{"tool": "...", "args": {...}}`。返回值仍要经过同一套 `validate_call`；
超时、连不上、JSON 不合法都会静默回退到规则解析，并在返回体的 `source` 里标成
`rule-fallback`。

> **公开演示请注意**：Render 免费实例没有 GPU，跑不动 7B 模型。所以线上默认
> `AGENT_LLM_ENABLED=false`，用规则解析；本地答辩时再打开 Ollama。
> 这样"老师用手机打开公网链接"和"你在讲台上演示大模型"互不冲突。

### 4.3 在 RTX 5060 上启用

50 系是 Blackwell（sm_120），需要较新的运行时：

```bash
ollama --version                  # 建议 0.3.0 以上
ollama pull qwen2.5:7b            # 约 4.7 GB，8GB 显存可跑
ollama run qwen2.5:7b "你好"      # 先确认模型能跑
curl http://127.0.0.1:11434/api/tags
```

如果用 PyTorch 做别的实验，先验证 `torch.cuda.is_available()`；旧版 PyTorch 会直接报
"不支持的 GPU 架构"。Ollama 自带运行时，一般不受影响。

## 5. 接口契约

`POST /api/v1/agent/command`，需要写权限。

```json
{ "text": "去 5,5 巡检", "confirm": false }
```

```json
{
  "text": "去 5,5 巡检",
  "understood": true,
  "tool": "start_patrol",
  "args": { "goals": [[5, 5]] },
  "source": "rule",
  "executed": true,
  "need_confirm": false,
  "ok": true,
  "message": "自动巡检已启动，共 1 个巡检点，机器人开始逐点前往。",
  "result": { "running": true, "current_goal": [5, 5], "progress": 0.0, "total": 1, "path_remain": 4 },
  "latency_ms": 0.5
}
```

| 字段 | 含义 |
|---|---|
| `understood` | 是否识别出了工具（听不懂 = false） |
| `tool` / `args` | 识别结果，前端原样展示，便于核对"它听成了什么" |
| `source` | `rule` / `llm` / `rule-fallback` |
| `need_confirm` | true 表示**尚未执行**，等前端带 `confirm=true` 再来一次 |
| `executed` / `ok` | 是否执行 / 是否成功（两者分开，便于区分"没执行"和"执行失败"） |
| `message` | 给人看的一句话 |
| `latency_ms` | 解析 + 执行耗时 |

执行完成后，服务端还会广播一帧 `{"type": "agent", "data": {...}}`，让其他客户端
（比如讲台上的电脑）同步看到"手机刚下发了什么指令"。

## 6. 前端

`AgentPanel.vue` 放在右侧面板（桌面）与「更多详情」抽屉（手机）里，包含：

- 输入框 + 发送按钮，回车即发送；
- 最近 6 条对话（用户原话 / 系统结论），失败用琥珀色、成功用绿色；
- 工具名、耗时与解析来源（本地大模型 / 规则兜底）小字标注；
- `need_confirm` 时出现「确认执行 / 取消」；
- 三个示例指令按钮（离线/在线文案略有不同）；
- 底部说明"只支持白名单动作，破坏性操作会先确认"。

离线模式（GitHub Pages 静态页）下没有后端，`frontend/src/services/agent.js` 承担与
Python 版等价的解析与校验职责，工具集合、提示文案与返回字段逐项对齐；在线模式
（`?backend=` 或同源部署）整句提交给后端，由后端决定用规则还是大模型。
两种模式的差异只体现在 `source` 字段上。

## 7. 演示脚本（30 秒）

| # | 说 | 预期 |
|---|---|---|
| 1 | "现在状态怎么样" | 报出坐标、电量、模式、巡检进度 |
| 2 | "去 5,5 巡检" | 地图上出现路径，机器人开始斜向移动 |
| 3 | "规划到 15,8 的路线" | 只出预览与耗电预算，机器人不动 |
| 4 | "把 12,8 的障碍清掉" | 先弹确认；确认后扣 5% 电量、障碍消失 |
| 5 | "回充电点" | 机器人规划回充电点的路径，模式变「返航充电」 |
| 6 | "停止巡检" | 回到手动模式 |

第 4 条是重点：**同一句话，先被拦一次**。这能直观说明"模型没有权限，代码才有"。

## 8. 评估与已知边界

已覆盖（自动化测试）：

- 11 类中文说法的意图识别、中文标点 / 括号坐标；
- 白名单外工具、越界目标、屏障目标、非障碍清障、边界编辑、撞墙移动的拦截；
- 破坏性操作的"未确认不改状态 / 确认后生效"；
- 巡检、规划、回充、状态查询在真实引擎上的行为；
- REST 返回字段完整性与空指令 422。

尚未做（答辩时主动说明）：

1. **规则解析不是通用 NLU**：换个说法可能听不懂，这是"宁可不动"的代价；
2. **没有多轮对话**：每条指令独立解析，不支持"再往左一点"这类指代；
3. **没有函数调用微调**：靠提示词约束 JSON，7B 模型偶尔仍会给出非法参数，
   所以校验层必须存在；
4. **没有语音入口**：浏览器语音识别可作为后续扩展，核心链路不用改；
5. **没有多机器人协同**：工具层是单机语义，多机需要引入 robot_id 与任务分配。
